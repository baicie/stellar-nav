# 天枢导航 v0.0.1-beta.0 Android 内测版

这是 Flutter + Rust 架构重建后的首个 Android 内测版本。它用于验证太阳系地图、科学数据、时间轴、教学路线、图层和模拟导航闭环，不是正式稳定版，也不能用于真实航天任务设计、飞行控制或安全决策。

## 下载

- `astro-nav-android-arm64-v8a.apk`：绝大多数近年的 Android 真机；
- `astro-nav-android-armeabi-v7a.apk`：仍使用 32 位 ARM 的旧设备；
- `astro-nav-android-x86_64.apk`：x86_64 Android 模拟器或少量对应设备；
- `release-metadata.json`：包名、版本、ABI、签名证书和每个 APK 的摘要；
- `SHA256SUMS.txt`：三个 APK 与元数据文件的 SHA-256 校验值。

本次不提供通用 APK、32 位 x86 包、AAB 或 iOS 包。每个 APK 只包含文件名声明的 ABI，并由 GitHub Actions 使用受控 release keystore 签名。

GitHub Release 在资产完整校验后才从 Draft 发布，并由仓库 immutability 设置锁定；`v*` 标签规则集禁止发布后移动或删除。发布流程不会覆盖已有标签、Release 或资产。

- 应用 ID：`com.baicie.astro_nav`
- 版本：`0.0.1-beta.0`
- 基础 versionCode：`1`
- 分包实际 versionCode：`armeabi-v7a=1001`、`arm64-v8a=2001`、`x86_64=4001`
- 签名证书 SHA-256：`D4:CC:2E:B0:73:4E:E8:38:FF:1E:0A:B3:69:EF:2A:64:B8:FA:89:C2:C3:AD:93:47:9F:47:86:9A:A6:D5:DA:18`

旧 Expo 版本使用 `com.baicie.stellarnav`。这次 Flutter 重建采用新的应用 ID，因此会作为独立 App 安装，不能覆盖旧版本；两者可以暂时共存。

## 安装与校验

先在设备信息或 `adb shell getprop ro.product.cpu.abi` 中确认 ABI，再下载对应 APK。将三个 APK、`release-metadata.json` 和 `SHA256SUMS.txt` 放在同一目录后执行：

```bash
sha256sum --check SHA256SUMS.txt
```

校验通过后，按 Android 系统提示允许本次来源安装。内测设备后续可以直接安装使用相同应用 ID、同一签名证书且 `versionCode` 更高的版本。

## 已知限制

- 天体位置、转移窗口、航时、Delta-v 与风险均为明确标注的数据快照或教学模型，不是实时星历；
- 当前只提供二维太阳系导航，没有真实 3D、行星表面导航、在线遥测或账号系统；
- 空间天气和风险图层是科普示意，不提供任务级预测；
- 本版本尚未经过大规模机型兼容性测试，建议只安装在内测设备上。

## 回滚

发布标签和已有资产不覆盖、不移动。若发现阻断问题，将把 GitHub Release 标记为已撤回并停止推荐下载，在 `main` 修复后以更高 `versionCode` 发布同证书签名的新 beta。Android 不允许较低 `versionCode` 直接覆盖回滚；需要立即退出本版本时，应卸载应用，这会同时清除本地应用数据。
