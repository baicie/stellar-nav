# ADR-0003: 把数据性质与来源作为强制领域边界

## Status

Accepted

## Date

2026-08-06

## Context

天枢导航同时展示公开科学资料、教学推导、任务模拟和科幻设施。视觉风格有意营造真实导航感，这会放大用户把模拟值误认为观测事实的风险。仅在页面底部放一条总免责声明不能说明每个值的来源和性质。

## Decision

领域只允许四种数据性质：

- `observed`：有可追溯公开来源的观测或权威参数快照；
- `derived`：依据已声明输入和方法推导、整理或换算；
- `simulated`：由教学路线或任务模型生成；
- `fictional`：为叙事设计，现实中不宣称存在。

每个目录对象、轨道参数组和科学字段必须携带 `provenance`：`nature`、`sourceId` 和中文方法 / 限制说明。每个来源必须提供稳定 ID、标签、URL 和 UTC 访问时间。

`observed` provenance 必须引用带有效 UTC 访问时间的公开 HTTP(S) 来源；版本化的内部 URN 只用于 `derived`、`simulated` 或 `fictional` 模型与设定。

具体口径：

- 真实天体和 ISS 的 J2000 简化开普勒位置是 `derived`，不能称为实时星历；
- 虚构设施的轨道参数、科学字段与位置继续保持 `fictional`，不能因为参与计算而降成 `derived` 或 `simulated`；
- 轨道相位是教学基准，轨道参数组的 provenance 必须如实说明这一限制；
- 基于霍曼目标相位、局部轨道周期和目录演示相位的教学窗口评分是 `simulated`，不能称为任务级发射窗口；
- 路线航时、Delta-v、通信时延范围、风险和推荐分是 `simulated`；
- 阿尔忒弥斯月面基地、晨星火星港和地月 L1 中继站是 `fictional`；
- ISS 使用公开参数与静态教学轨道，不能显示成实时 ISS 位置；
- 空间天气与风险图层当前是教学示意，不能包装成实时预报。

UI 同时使用中文文字与视觉标记表达性质，不能只靠颜色。数据不足时显示“暂无可靠数据”，不补造数值。

## Alternatives Considered

### 只给整张路线或整页标一个性质

- 优点：数据结构简单；
- 缺点：同一对象的不同字段可能来自不同性质，页面级标签会掩盖差异；
- 结论：对象级与字段级都保留 provenance。

### 只保存来源 URL

- 优点：字段更少；
- 缺点：URL 无法表达推导方法、模拟假设或虚构状态；
- 结论：来源引用与性质说明都必须存在。

### 用“真实 / 虚构”二分类

- 优点：用户容易理解；
- 缺点：会把观测、推导和模拟混为一谈，而三者可信度和用途明显不同；
- 结论：采用四类封闭枚举。

## Consequences

- 科幻表达不会隐去科学证据边界；
- 数据目录、轨道参数、Dart DTO、Rust struct、测试和 UI 都要传播 provenance；
- 新数据导入必须经过离线校验和来源审查；
- 数据性质变化属于 contract 变化，需要测试、文档和必要的 schema 迁移；
- 当前 App 必须持续显示教学与非操作用途免责声明。
