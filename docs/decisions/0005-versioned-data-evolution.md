# ADR-0005: 以版本化数据适配器承接真实天文数据演进

- 状态：Accepted
- 日期：2026-08-05

## 背景

MVP 需要离线启动、确定性演示和可审计的数据性质；后续又可能接入 Gaia、SIMBAD 或 NASA 数据。直接把在线请求塞进界面会破坏离线体验，也会把观测、推导、模拟和虚构值混在一个对象里。

## 决策

当前使用仓库内版本化的演示目录，所有天体目录字段、地图位置、飞船参数和路线结果分别保留来源性质。未来接入真实数据时，先实现独立的数据适配器和版本化快照，在适配器边界完成来源许可、模式校验、单位归一化、质量报告和 provenance 映射；UI 只能消费同一领域类型，不能直接请求在线 API。

只有同时满足以下条件才升级到在线管线：数据许可可公开分发、快照可复现、离线缓存有明确失效策略、异常数据不会进入路线计算，且迁移前后核心回归值已锁定。需要大规模解析或路线计算时，先在 Worker 中运行；只有在数据规模和更新频率证明必要时，才评估 Rust 后端。

## 被否决的方案

### 在组件中直接请求天文 API

会引入网络失败、渲染时序和来源标注泄漏，无法保证首屏和离线体验。

### 现在就建设后端数据平台

MVP 数据量和更新频率不足以证明运维成本，且会扩大账号、部署和隐私边界。

## 结果

MVP 保持轻量、可测试和可离线运行；未来数据接入的成本集中在适配器、校验和许可审查，而不是重写 UI。在线数据、Worker 或后端均需新增 ADR 和迁移测试，不得绕过现有 provenance 边界。
